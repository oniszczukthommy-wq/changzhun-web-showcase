# 唱准 · 中文网页个人版

基于 [dsmurrell/onkey](https://github.com/dsmurrell/onkey) 修改，原项目作者 Daniel Murrell，保留 MIT 许可和第三方声明。第一版供这台 Mac 本机使用。

## 平台支持

当前安装版仅支持 Apple Silicon Mac。正在按 Windows 11 x64 做共享算法和网页兼容准备，尚无可用 Windows 安装包；范围、自动检查和后续步骤见 [Windows 支持准备](docs/windows-support.md)。

## 打开与使用

1. 打开 `/Applications/唱准助手.app`，或双击本目录中的 `启动唱准.command`。
2. 浏览器打开 **http://127.0.0.1:47322**。助手启动后会自动打开这个地址；关闭网页不等于退出助手。
3. 按中文设置向导允许“麦克风”和“系统音频录制”，声音权限完成后，在练唱页连接 QQ 音乐所用的浏览器。权限必须由你在 macOS 弹窗中确认。
4. 在练唱页的“QQ 音乐网页版”卡片选择 Ego Lite / Google Chrome / Safari / Edge / Brave 并点“连接”，按提示允许 macOS 自动化权限和浏览器的“允许来自 Apple 事件的 JavaScript”。点“打开播放器”进入 QQ 独立播放器；列表为空时，点“选歌首页”，在所选浏览器登录、选歌并手动播放，保持弹出的独立播放器标签页打开。第一次完整播放用于学习旋律；学习完成后再唱，会显示实时音准与音符轨道，并保留练唱结果和录音。
5. “历史”可查看评分和回放；“曲库”可再次练习。耳机通常能减少伴奏串入麦克风。
6. 退出时，在唱准助手菜单选择“退出唱准助手”。后台可能需要短时间保存本次学习结果。

网页无需 Node.js、开发服务器或云服务。辅助程序包含原版音频采集、人声分离、音高识别和评分引擎。仅监听 `127.0.0.1`，其他设备不能直接连接。

## 已提供

- 中文界面、首次设置、音准提示、练唱反馈、设置及片段导出文字。
- 12 个中文主题歌单、120 首歌曲；支持按歌名或歌手搜索、收藏、主题筛选及复制歌单。
- Apple Music、网易云音乐、QQ 音乐、Spotify 搜索入口。点击后进入对应平台，播放与订阅由平台处理。
- QQ 音乐网页版实验性接入：读取歌曲名、歌手、专辑和网页进度；支持当前播放器暂停、继续、上一首、下一首及跳转。
- 网页控制原版核心功能：实时轨道、学习进度、曲库、历史、录音回放、音频设备设置和诊断导出。
- 原版项目与已安装的 OnKey 保留。此版本名称和图标为“唱准助手”，数据目录独立。

## 当前边界

- Shazam 在线识曲依赖原作者的签名权限，本地修改版禁用。新歌曲可通过 QQ 音乐网页、Apple Music 或 Spotify 获取歌曲信息。QQ 网页不依赖 Shazam。
- 网易云目前仍是找歌入口，尚未接入自动跟随。
- QQ 的进度来自页面显示的百分比和总时长，是估算值；后台标签页限速、缓冲及站点更新可能影响精度。请关闭同一浏览器里其他有声音的标签页，且只保留一个正在播放的 QQ 播放器。
- QQ 登录、会员和试听权限由 QQ 音乐控制。程序不会绕过播放限制。历史中切换到未打开的歌曲，会先打开其官方详情页，需要你手动点播放；当前曲目可以直接重播。
- 中文歌词依赖 LRCLIB 是否有同步歌词。汉字歌词使用逐行时间，不使用原版英语逐词对齐模型；缺歌词时音准轨道与评分仍可工作。
- 精简模式在当前网页内显示，暂不提供跨 App 的置顶悬浮窗。
- 歌单收藏保存在当前浏览器中；练唱数据保存在 Mac。换浏览器不会迁移歌单收藏。
- 首次真实练唱需完成系统声音权限，以及所选浏览器的自动化授权；未经授权不可能验证实际人声采集。

## 数据位置

- 练唱记录、歌曲分析、设置：`~/Library/Application Support/local.changzhun.mac/`

- 原版 OnKey 数据仍在 `~/Library/Application Support/audio.onkey.app/`，没有自动迁移或修改。
- 运行日志：新目录的 `records/logs/`。

## 开发与检查

源码分支：`codex/changzhun-web-zh`。

前端位于 `ui/`，QQ 网页适配在 `src-tauri/src/qqmusic.rs` 和 `qqmusic-page.js`；本地 HTTP/SSE 桥接位于 `src-tauri/src/web.rs`，公开命令白名单位于 `src-tauri/src/web_dispatch.rs`。请求通过随机会话令牌、Host 和 Origin 检查限制为本机网页。

已安装依赖与 Rust 工具链后，在仓库执行：

```sh
./tools/build-changzhun.sh
```

构建输出：`src-tauri/target/release/bundle/macos/唱准助手.app`。安装更新前退出正在运行的唱准助手，再将构建产物复制到“应用程序”。不要使用原项目默认发布配置，它仍保留原项目的标识与构建方式。

运行中的助手可检查：

```sh
python3 tools/test-local-bridge.py
```

该检查覆盖页面、原生命令、设置读写回滚、SSE、访问限制；不会请求麦克风或自动播放音乐。

## Ego Lite 使用注意

- 在普通浏览窗口打开 QQ 音乐并点击具体歌曲的“播放”，保留独立播放器 `https://y.qq.com/n/ryqq_v2/player`。仅打开 QQ 首页不会开始跟唱。
- 如 QQ 提示无法自动播放，需要手动点一次“开始播放”。
- 验收时发现 Ego 自动化工作区的标签页不会出现在其 AppleScript 标签页列表中；请使用普通浏览窗口。
- Ego Lite 的主程序标识为 `com.citrolabs.ego.lite`，音频辅助进程使用 `com.citrolabs.ego.helper`，采集已按实际辅助进程修正。
- 本地重新构建和签名后，macOS 可能要求重新授权“唱准助手”。授权浏览器不能替代授权助手。
- 系统音频的底层权限预检在本机可能仍显示“ask”，即使实际采集已经可用；应结合向导与真实声音验证，不应仅凭该预检反复要求授权。
- 验收期间歌词服务曾返回 HTTP 503，稍后恢复并完成歌词对齐。歌词可用性受服务和曲目覆盖情况影响。

## 连接引导改进（2026-10-31）

- “打开播放器”直接打开 QQ 独立播放器，“选歌首页”单独打开音乐首页，避免只停留在首页而无法跟唱。

- QQ 页面元数据加载中缺少歌曲链接时安全等待，不使读取脚本异常。
- Ego Lite 的提示明确要求使用普通浏览窗口。

本次更新验证：189 项 Rust 测试、9 项前端与页面解析测试、生产构建、安装签名和本地桥接检查通过。新播放器入口已在安装后的页面操作验证。安装更新后 macOS 重置声音权限，当前版本真人跟唱验收需重新确认授权。
